# タスク: Keyball61 トラックボールのセンサー回転ズレを根本修正する

## 背景・症状
- キーボード: Keyball61(自作キーボードキット、分割式、親指トラックボール搭載)
- トラックボール周辺のパーツはAliExpressで購入した互換品を使用しており、コントローラーは標準のATmega32U4 Pro Microではなく、RP2040ベースの互換ボードを使用している
- ファームウェアはUF2形式で書き込み済み。キーマップの編集はRemap経由で行っている
- **症状**: トラックボールを指で固定して円を描くように回転させると、カーソル(および特にスクロール操作時)が円運動に加えて一定方向に少しずつドリフトしていく
- **切り分け済みの事実**: 円を描く向きを逆にすると、ドリフトの方向も反転する。これは「センサーチップが物理的にわずかに回転して実装されている(光学的な軸ズレ)」ことを強く示唆する。CPIやスクロール分周設定など、ソフトウェア側の一般的な設定ミスではない

## リポジトリ
- 公式リポジトリ: https://github.com/Yowkees/keyball
- 該当ファームウェア: `qmk_firmware/keyboards/keyball/lib/keyball/keyball.c`(共通ロジック)、および `keyball61/keymaps/` 配下の該当keymap
- 参考: `keyball_on_apply_motion_to_mouse_scroll` という関数がweak属性で定義されており、ユーザー側のkeymap.cで同名関数を再定義することでスクロール変換ロジックを上書きできる。ただしこれはスクロール専用のフックであり、通常のカーソル移動には適用されない点に注意

## やってほしいこと(優先順位順)

1. **根本原因の特定**
   - `keyball.c` を精査し、センサーから読み取った生の移動量(x, y)が `keyball.this_motion` / `keyball.that_motion` に格納される箇所(おそらく `pointing_device_task_kb` 周辺、もしくはPMW3360/3389系ドライバのreport取得処理)を特定する
   - 通常のカーソル移動用処理(`motion_to_mouse`等)とスクロール用処理(`keyball_on_apply_motion_to_mouse_scroll`)の両方が、この生データを参照していることを確認する

2. **回転補正の実装(根本修正)**
   - スクロール専用のweak関数だけを上書きするのではなく、**カーソル移動とスクロールの両方に共通して効く場所**(生の移動量を消費する直前の1箇所)に、回転行列による補正を追加する
   - 浮動小数点を避け、固定小数点演算(例: cos/sinを1024倍した整数)を使うことでRP2040/AVR双方で軽量に動作するようにする
   - 補正角度は `config.h` かキーマップ内の `#define` で簡単に変更できる形にし、ビルドし直すだけで角度を調整できるようにする
   - 回転方向(符号)も定数で切り替えられるようにしておく

3. **ビルド環境の確認**
   - このボードがRP2040ベースの互換品であることを踏まえ、Yowkees/keyballリポジトリが素のままRP2040向けにビルド可能か確認する(QMKのconverter機能や、コミュニティ製のRP2040対応フォークが必要な可能性がある)
   - 既存のUF2ファイルがどのビルド設定(keymap名、converter設定)から生成されたものかを推測または確認し、同じ設定で自分の変更を反映したUF2をビルドできるようにする
   - 必要なQMK環境(qmk_firmwareのセットアップ、Dockerまたはqmk-msys等)がなければ、その構築手順も含めて進める

4. **検証方法**
   - まずは1つの妥当な初期角度(例: 5度)でビルド・書き込みし、円運動テストでドリフトの残り具合を確認する
   - ドリフトが残る場合、角度を大きく/小さく振って二分探索的に追い込む(角度だけでなく、符号が逆かどうかも切り分ける)
   - 最終的にドリフトが実用上気にならないレベルまで収束させる。目安として、意図的に円を描く動作でのY軸方向の累積ズレが体感できない程度まで追い込む
   - 通常のカーソル移動、スクロール操作の両方で改善を確認する

## 制約・注意点
- スクロールスナップ機能(`KEYBALL_SCROLLSNAP_ENABLE`)を使っている場合、その処理ロジックを壊さないよう、既存のスクロール変換ロジック(除算・余りの扱いなど)はそのまま維持しつつ、回転補正だけを前段に追加すること
- 分割キーボードなので、トラックボールが搭載されている側(左右どちらか)でのみこの補正が必要。`is_left` 等のフラグで正しい側にのみ適用されるよう注意する
- 変更後は必ずビルドが通ることを確認し、変更点(補正角度・実装箇所)をコメントとして残しておくこと

## ゴール
トラックボールで円運動をした際に発生するカーソル/スクロールの一方向へのドリフトを、ファームウェアレベルでの回転補正によって解消し、書き込み可能なUF2ファイルとして出力する。
